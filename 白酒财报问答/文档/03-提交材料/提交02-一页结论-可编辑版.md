# 白酒财报 RAG 知识库 —— 一页结论

**系统**：12 家 A 股白酒上市公司 84 份年报/半年报（13,584 页 → 39,702 个文本块），
本地解析建索引，向量 + BM25 混合召回，本地 4B 模型带出处作答，每个数字可回溯到原文块与页码。

**实验链路**：v1 基线 **3/10** → v1 优化后 **7/10** → v2 全新题 **4/10** → v2 通用兜底后 **7/10**

---

## 1. 第一版主要失败在哪

基线只答对 3 题，失败集中在**检索定向**，不是模型不会说话：

| 失败 | 表现 |
|---|---|
| **指标/口径定向缺失** | 问毛利率答营业收入；问「经销商已打款未确认收入」映射不到「合同负债」 |
| **年报 / 半年报混召回** | 同一年两种报告并存时，取到半年报的数当年度数，同比口径直接错 |
| **全局问法没展开** | 「哪些白酒公司…」只召回 6/12 家，结论必然不完整 |
| **表格读不出目标行** | 宽表里取到「分渠道小计行」而非合并口径（−1.08% vs 真值 −1.21%） |
| **跨公司覆盖不均** | 点到名的几家里，有的公司只召到 1 块且是无关块 |

共同点：**答案所需的原文其实在库里，只是没被召回来；召错行比召不到更危险**。

## 2. 做了哪些改进（五步串行，每步只改一个模块）

1. **指标定向**（`metrics.py`）：给营业收入、合同负债、毛利率、净利润、产销量 5 组指标
   做同义扩展 + 加权 + 定向配额（保证目标块至少占一半席位，加权救不回排几千名的块）。
2. **报告期区分**（`retriever.py`）：明确说"半年报"走硬过滤；只说年份时优先年报、不足时软加权，避免零召回。
3. **全局路由**：三级正则识别「全部白酒公司 / 12 家 / 哪些公司」，展开为 12 家，每家各召 2 块。
4. **净利润规则**：补「归母净利润 / 净利润」口径规则，跨公司题每家用同一口径参数。
5. **生成侧**：先按表头定位目标行再读数；单位照抄原文；跨公司先逐家列值与单位再比较；禁止自算合计。

v1 正确率 **3/10 → 7/10**。

## 3. 哪些改进真正泛化（换题后依然成立）

- **报告期识别**：v2 里 4 道涉及年份的题全部落对报告期，其中 Q3 只给"2025 年"、
  而该公司年报与半年报都有 ROE，仍正确落到年报。
- **全局 12 家覆盖**：v2 两道全局题都是 12 家 × 2 块均匀分布，`coverage_ok=True`，
  v1 基线"只召 6 家"的问题没有复发。
- **单位与格式**：v1 乱补"万元"的病没复发；v2 里「% 与百分点」「元/股」「元」都写对了。
- **失败时不编造**：v2 三道检索失败的题全部诚实答"材料不足"，零幻觉。

一句话：**泛化的是路由层（找哪家、找哪一期、找哪张表），不是指标层。**

## 4. 哪些地方出现过拟合

- **指标定向严重依赖 `metrics.py` 的 5 条白名单规则**。v2 三道失败题（存货、货币资金、销售费用）
  **全部在规则外，全部召不回来**；而 v1 里"跨公司对、全局对"靠的正是营收、毛利率、净利润——**全在白名单内**。
  换指标后跨公司 0/2、全局 0/2。
- **结论**：v1 的 7/10 里，真本事和"背题"大约各占一半。系统学会的是"这几类指标怎么做题"，
  不是"怎么定位一个陌生的会计科目"。**净泛化提升只有 +10pt（30% → 40%），v1 内部提升却是 +40pt。**

## 5. 最后一轮：为什么用通用结构信号代替逐科目硬编码

继续给存货、货币资金、销售费用各写一条规则**只是把白名单加长，过拟合不会消失**——
下一个没写过的科目照样崩。所以最后一轮改成问一个更一般的问题：

> **"财报里，什么样的文本块才装着科目数据？"**

答案与科目无关，只与**报表结构**有关。新增 `代码/科目兜底.py`（**仅当五组规则都没命中时启用**）：

| 通用信号 | 系数 | 作用 |
|---|---|---|
| 不是表格块（叙述段） | ×0.55 | 压掉"原因说明/会计政策" |
| **没有任何千分位金额** | **×0.35** | 压掉"40、销售费用 单位：元"这类**空表头** |
| 科目行形状（汉字科目名 + 分隔符 + 千分位金额） | ×2.4 | 捞起真正带数字的行 |
| 主表表头（主要会计数据 / 三大报表 / 资产构成表） | ×2.2 | 优先主表，压附注明细 |
| 受限 / 抵押 / 子公司 / 关联方 / 会计政策 | ×0.5 | 压掉非目标口径 |

科目词典（约 80 条通用会计科目）**只做"写法 → 标准科目名"的归一，条目之间零权重差异**；
跨公司题仍在每家公司内部独立执行同一套逻辑。

**效果**：规则外科目的真值块 **0/3 → 3/3**（Q6 存货、Q7 货币资金、Q8 销售费用），
其中 Q6「压在仓库里还没卖出去的那些货」**压根没识别出科目名**，靠实义词 + 结构信号照样捞中；
v2 正确率 **4/10 → 7/10**，且对规则内题目**零干扰**（Q10 召回块序列与优化前完全一致）。

**这轮的收获不是多对了 3 道题，而是证明了"用结构信号替代逐科目硬编码"这条路走得通。**

## 6. 最终仍存在的局限

| 局限 | 表现 | 归因 |
|---|---|---|
| **单位判断** | Q8 三家销售费用数值与结论全对，但单位写成"万元"（原文为元），模型还自辩"按财报惯例统一处理" | 生成侧：小模型在跨公司多列材料里容易"顺手统一单位" |
| **正负号判断** | Q10 把 +7.07%、+7.80% 判成"下滑"，真下滑 4 家全中却多报 2 家；同一份答案两次排序还不一致 | 生成侧：方向判断 + 自设"显著性"门槛 |
| **引用空白符归一化** | Q2 原文 `528,600,000 股` 带空格，回答 `528,600,000股` 被判不匹配 → 答案全对却被追加"不予采信"，自相矛盾 | `citations.py` 归一化只处理了全角/半角与千分位，没处理空格 |
| **数字可追溯 ≠ 取对了行** | v2 Q9 的 6,622,531,791.91 确实能在汾酒 p29 表里找到（校验通过），但那是另一口径，合并口径应为 5,980,102,739.72 | 引用校验只能证明"数字来自这块"，不能证明"取的是正确的那一行" |

**这三处都在生成侧与校验器，不在检索环节；按要求停止开发，未做修改，作为已知局限保留。**

---

### 一句话总结

先测后改、每题留痕，让我看清楚「7/10」里有多少是真本事：路由层（找哪家 / 哪一期 / 哪张表）的改进
**真的泛化**了，指标层的白名单规则**只是把题背会了**；最后一轮用"科目无关的通用结构信号"兜底，
才把泛化能力补回来（未知指标召回 0/3 → 3/3），剩下的缺陷全部集中在**单位、正负号、引用归一化**
这三处生成侧/校验器问题上。
