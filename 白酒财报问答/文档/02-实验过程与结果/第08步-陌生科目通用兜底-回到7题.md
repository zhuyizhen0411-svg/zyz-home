# 第 12 步（最后一轮）：陌生财务科目通用兜底

> 目标不是让 v2 拿 10/10，而是验证「**未知指标能不能比以前更容易找到正确原文**」。
> 本轮只改这一件事；报告期识别、公司路由、metrics.py 五组规则、生成侧、引用追溯、页面**全部未动**。

## 一、做法：不认识科目，只认识"财报里什么样的块装着科目数据"

新增 `代码/科目兜底.py`，在 `retriever.search()` 里挂钩：**仅当 metrics.py 的 5 组规则都没命中时**才启用，与规则内题目的行为完全隔离。

1. **从问句识别科目/指标词**：一张《企业会计准则》常用科目平铺词典（约 80 条，资产/负债/权益/损益/现金流/比率/分红），只做「写法 → 标准科目名」的归一，**条目之间没有任何权重差异**，用于给 BM25 加一路关键词。
   - Q7「账上的货币资金」→ 货币资金；Q8「销售费用」→ 销售费用；Q1「基本每股收益」→ 基本每股收益；Q9「经营活动产生的现金流量净额」→ 同名。
   - Q6「压在仓库里还没卖出去的那些货」→ **没识别出科目**，走下面的兜底路径。
2. **第二路 BM25**：原句 + 标准科目名 + 实义词 + **通用报表表头词**（本期期末数 / 上年同期 / 占总资产的比例 / 主要会计数据 / 项目名称）。表头词是结构词，与科目无关。
3. **通用结构加权**（无任何科目专属权重）：
   | 信号 | 系数 | 作用 |
   |---|---|---|
   | 不是表格块（叙述段） | ×0.55 | 压掉"原因说明/政策"类文字 |
   | 没有任何千分位金额 | ×0.35 | **压掉"40、销售费用 单位：元"这类空表头** |
   | 科目行形状（汉字科目名 + 分隔符 + 千分位金额） | ×2.4 | 捞起真正带数字的行 |
   | 主表表头（主要会计数据 / 资产构成表 / 经营情况表 / 三大报表） | ×2.2 | 优先主表，压附注明细 |
   | 块里有/没有问到的科目名 | ×1.9 / ×0.5 | — |
   | 问句没科目名时命中实义词 | ×1.5 | Q6 这类纯口语问法 |
   | 非目标块（受限/抵押/子公司/关联方/被投资单位/会计政策/定义） | ×0.5 | 压掉受限货币资金、子公司表、政策段 |
4. **定向配额**：复用 metrics.py 那套「目标块至少占一半席位」的机制（加权救不回排几千名的块），掩码 = 表格 + 有金额 + 主表/科目行形状 + 非受限非子公司非政策。
5. **跨公司题逐家执行同一套逻辑**（`route()` 未改），没有为任何公司写答案。

## 六、仍然答错的题及原因

1. **Q10（全局扣非净利润下滑）— 仍错**。命中 metrics.py 的"净利润"规则，**兜底按设计不介入**。错因仍是生成侧的方向判断：把水井坊 +7.07%、今世缘 +7.80%（实为增长）当成下滑，真下滑的 4 家（酒鬼 -98.75 / 舍得 -76.64 / 洋河 -30.56 / 口子窖 -5.15）全中。这属于「生成侧正负号判断」，不在本轮范围。
2. **Q8 单位** — 数值与比较结论全对，但三个数都写成"万元"（原文为元），模型还自己加了段"结合财报惯例统一按万元处理"的辩解。与 v1 Q5（销售费用单位错）是同一处生成侧弱点。
3. **Q2 引用** — 数值全对，但原文是 `528,600,000 股`（数字与单位间有空格），回答写 `528,600,000股`，校验判不匹配 → 答案末尾被追加"材料不足…不予采信"，自相矛盾。这是 `citations.py` 的数字归一化缺陷，不在本轮范围。

## 七、结论

- 用**通用报表结构信号**替代「逐科目写规则」是可行的：规则外科目的召回从 0/3 提升到 3/3，v2 正确率 40% → 70%，且规则内题目零干扰。
- 剩余失败全部集中在**生成侧**（单位换算、正负号方向）与**引用校验器**（空白符归一化），这两块本轮按要求未改。

**到此停止，不再继续优化。**
