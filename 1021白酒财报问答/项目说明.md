## 1. 项目目标

构建一个**可追溯**的财报问答系统：用户用自然语言（含口语、简称、同义说法）提问，系统
从真实的财报原文中找到对应段落/表格行，由本地大模型带**出处编号**作答，并且**每一个数字
都能点回它真正来源的原文块与页码**。

设计上坚持三条底线：

1. **只依据材料回答**，材料里没有就答「材料不足」，不推测、不编造、不用常识补全；
2. **数字照抄原文**，禁止换算、禁止跨行借用单位；
3. **引用可追溯**，答案里的每个数字都要能被 `citations.py` 回溯到具体块 + 公司 + 年份 + 报告类型 + 页码。

## 4. RAG 流程

```
代码/公司清单.py         12 家公司清单（代码 / 市场 / 档位）
代码/抓取公告索引.py       拉公告索引（深交所 API + 巨潮 API），按报告期挑"全文"
代码/下载财报.py  并发下载 PDF + PDF 头/大小校验
代码/校验财报.py       页数与正文可提取性校验
        ↓
代码/解析财报.py      PDF → 页级正文 + 表格（pdfplumber，多进程 8 路）
代码/切块.py             页级文本 → 文本块（正文 ~700 字/重叠 100，表格整块 ≤900 字）
代码/建索引.py       BM25 索引 + 向量索引（fp16，支持断点续跑）
        ↓
代码/检索引擎.py         检索：路由 → 向量 + BM25 混合 → RRF 融合 → 定向加权 → 重排
代码/科目兜底.py           陌生科目通用兜底（仅当指标规则未命中时启用）
代码/指标规则.py           5 组常见指标的定向规则（营收/合同负债/毛利率/净利润/产销量）
代码/原文聚焦.py           「聚焦原文行」视图：从宽表里挑出与提问相关的行
        ↓
代码/生成回答.py               本地 Qwen3-4B 生成带 [n] 出处的回答
代码/引用追溯.py         引用追溯：把答案里的每个数字核对回原文块，标 ok / bad / no_citation
代码/网页服务.py             FastAPI 服务 + 两个网页
代码/批量评测.py          批量评测（路由 / 召回 / 回答 / 引用 / 追溯 全程留痕）
代码/冒烟测试.py        冒烟测试
```

### 切块与元数据

每个块都带完整出处，且**出处前缀会写进参与向量化的文本**，让向量也带上出处信息：

```json
{"company":"古井贡酒","code":"000596","year":2023,"rtype":"年报",
 "section":"第十节财务报告","page":170,"doc_id":"000596_2023_年报","block_type":"table"}
```

文本前缀形如：`【古井贡酒｜2023年年报｜第十节财务报告｜第170页】`。
表格块保留行列关系（行内用 `列 | 列` 还原），单元格内换行/空格全部去掉（否则中文财报数字会被切碎）。
目录页、释义页、纯页码页已过滤。

## 5. 向量检索 + BM25（混合召回）

| 环节 | 做法 |
|---|---|
| 向量 | `Qwen/Qwen3-Embedding-0.6B`，1024 维，mean pooling + L2 归一化，本机 MPS fp16 前向 |
| BM25 | jieba 分词 + Okapi BM25（k1=1.5, b=0.75），词表约 8.5 万 |
| 融合 | **RRF**（向量权重 1.0 / BM25 权重 1.4）——财报里的精确术语和数字，词频匹配比语义更可靠 |
| 指标定向 | `metrics.py` 对 5 组常见指标做「同义扩展 + 加权 + 定向配额」；未命中时交给 `subject.py` 通用兜底 |
| 重排 | 先宽召回 60 块，再按「同源收敛（同公司同页最多 2 块）+ 数字密度 + 表格块加权」重排 |
| 硬过滤 | 公司 / 年份 / 报告类型（年报 / 半年报）元数据前置过滤 |

**报告期区分**：`detect_period()` 识别问句是半年报还是年报。明确说「半年报/上半年」走硬过滤；
只说年份或问全年指标时优先年报，不足时软加权（×0.35）避免零召回 —— 专门解决「同一年既有年报又有半年报」的混召回。

## 6. 跨公司逐家检索

`Retriever.route()` 先判断问法：

| 路由类型 | 触发 | 行为 |
|---|---|---|
| `single-company` | 只提到 1 家公司 | 该公司内召回 top_k 块 |
| `multi-company` | 点到名的 2 家以上 | **每家各召回 per_company_k 块**（默认 3），再合并重排 |
| `global` | 「哪些白酒公司…」「12 家…」等全局问法 | 展开为 12 家，**每家各 2 块**，保证覆盖均匀 |

关键点：**跨公司题对每一家都用同一套参数、同一套逻辑执行**，没有为任何一家公司写特例答案。
评测脚本会输出 `company_distribution`（各公司召回块数）和 `coverage_ok`（涉及公司是否全部召回），
自动检查「漏掉某家公司」这类失败。

`subject.py` 的通用兜底同样在**每家公司内部独立执行**，保证跨公司题不会因为某一家召回失败而整体塌掉。

## 7. 引用追溯

答案里每个数字后面跟 `[n]`，`n` 是材料块编号。`代码/引用追溯.py` 做三层校验：

1. **逐句拆分**答案，识别句子中的数字与它标注的编号；
2. 到该编号对应的原文块里**查找这个数字**（原文做全角/半角、千分位、单位等归一化后再比对）；
3. 输出每个数字的三种状态：
   - `ok` —— 数字能在被引用块里找到；
   - `bad` —— 引用了某块，但数字不在那块里（取错行 / 串公司的典型症状）；
   - `no_citation` —— 数字后面没标编号。

若整句都没找到依据，自动追加「材料不足…不予采信」提示。
页面 `/api/chunk/{id}` 可以按块号取回原文与完整出处，供人工复核。

## 10. 安全与隐私说明

**本仓库不含任何敏感信息**：

- 不调用在线模型 API，**没有 API key / token / 密码 / 个人账号**；
- 代码中没有硬编码的个人路径（项目根目录由 `__file__` 推导）、没有 Cookie、没有账号信息；
- 财报数据全部来自交易所官网与证监会指定披露平台的**公开披露文件**；
- `.gitignore` 已排除 `.env`、`*.key`、`*.pem`、`secrets.*` 等，源码里也没有 `.env` 依赖；
- 生成模型 `mlx-community/Qwen3-4B-Instruct-2507-4bit` 与向量模型 `Qwen/Qwen3-Embedding-0.6B`
  都在**本机加载**，`HF_HUB_OFFLINE=1` 时完全离线。

提交前可自查：

```bash
grep -rniE "api[_-]?key|token|password|secret|sk-[A-Za-z0-9]{8,}" --include="*.py" --include="*.html" --include="*.md" .
```
