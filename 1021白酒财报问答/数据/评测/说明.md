# 评测数据目录说明

这个目录放的是**跑测试用的题集和跑出来的结果**（机器读的 JSON），
对应的人读报告在 `文档/01-题库/` 和 `文档/02-实验过程与结果/`。

## 一、三批题，三种身份

| 批次 | 文件 | 身份 | 能说明什么 |
|---|---|---|---|
| 第一批 | `题库1-最初的10道题.json` | **开发题** | 只说明「改过的地方有没有退步」，不能当成绩 |
| 第二批 | `题库2-全新10道题.json` | **开发题（原检验题，已污染）** | 第07步当检验题测得 4/10，随后第08–10步拿它反向调参，已经不是「没见过的题」 |
| 第三批 | `题库3-冻结金标-10道题.json` | **新题（检验题）** | 金标先哈希冻结，出题时没跑过系统 —— 这一批的分数才是可对外的成绩（**4/10**）。2026-10-21 整批重出，含 2 道跨公司全景题；旧版归档在 `历史/` |

冻结记录在 `题库/金标冻结记录.json`（题目与金标的哈希 + 冻结时间）。
改过题目或金标，`python 代码/冻结金标.py --verify` 就会报出来是哪一题被动了。

## 三、怎么重新跑

```bash
# 跑第一批题（默认）
python 代码/批量评测.py

# 跑第三批新题（检验用）
python 代码/批量评测.py --questions 数据/评测/题库/题库3-冻结金标-10道题.json \
                        --out 数据/评测/结果/结果10-第14步-题库3重建后检验.json

# 只跑第 6、7、8 题
python 代码/批量评测.py --questions 数据/评测/题库/题库2-全新10道题.json --ids 6,7,8

# 只看召回、不生成回答（很快）
python 代码/批量评测.py --no-llm

# 把三批题汇成一张逐题记录表
python 代码/逐题记录.py

# 全景题：按公司逐家取证，出覆盖地图
python 代码/全景取证.py --year 2026 --rtype 半年报

# 口径规则改过之后：用旧回答复核一遍，不重跑模型
#   --dry-run 只打印「旧提示 → 新提示」，不写文件
python 代码/补口径核对.py --result 数据/评测/结果/结果10-第14步-题库3重建后检验.json --dry-run
```

**结果 JSON 里每题都有**：路由类型、识别到的公司/年份/报告类型、
召回块清单与来源、最终回答、引用块、每个数字的可追溯状态、公司覆盖检查。
**逐题记录 JSON 在此基础上多了**：批次与身份、金标与出处、金标块在召回里排第几、
修复前与修复后的回答和判定。
