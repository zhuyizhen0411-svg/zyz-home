# 第 10 步 · 生成侧优化（读表 / 单位 / 跨公司口径）

> 本轮**只改生成环节**：`代码/原文聚焦.py`（新增）+ `代码/生成回答.py`（提示词与材料拼装两个函数）。
> **未触碰**：检索召回、`retriever.py` 的路由与公司识别、`metrics.py` 的指标定向权重、`citations.py` 的追溯校验、页面。

## 一、改了什么

### 1. 新增 `代码/原文聚焦.py` —— 给模型看的「原文行」视图

纯文本处理，不改召回结果；输出里每一行都原样取自被召回块，只做两件整理：

- **去掉空单元格**：`| 合同负债 |  |  | 7,529,047,335.12 |` → `合同负债 | 7,529,047,335.12`（数字与单位一字不动）

- **折行回填**：年报表格里一个单元格太长会另起一行（洋河/古井的同比值就落在下一行的后段列），
  把这类续行按列拼回同一行，否则模型读到的是「有金额、没同比」的残缺行。

筛选哪些行进视图，用的都是现成的通用信号：`detect_metric()` 给出的科目名（权重最高）、
问句里的实义中文词、同比类提问的加成词；**命中落在表头行时会连带给出它下面的数据行**——
否则「营业收入」只出现在表头、数据行里没有该词，模型依旧读不到数值。
行数按预算分配（先每块 3 行铺满所有公司，有余再放宽），保证 12 家题每家至少有一块上榜。

### 2. 提示词改写（`SYSTEM_PROMPT`）

| 条 | 新增/强化的要求 |
|---|---|

| 1 | **先找后答**：先按表头定位目标行的各列含义再读数；材料里存在该行时不得回答「材料不足」 |

| 3 | **单位**：表格行若没标单位，按财报披露惯例即为「元」；表内标注优先；叙述句按其句内单位；禁止换算、禁止跨行借用单位 |

| 4 | **口径**：同一科目多行时取合并口径，避开子公司/分部/小计/关联方明细 |

| 5 | **跨公司比较**：先列「公司 → 指标值 + 单位 + 同比」再比较；单位不同先保留原单位说明；确需换算时给出方向自检（元→万元是 ÷10,000） |

| 6 | 不得自行求和；判断“增长/下滑”只看同比正负符号，不得自设幅度门槛 |

### 3. 科目口径说明（通用会计知识，不含任何公司/年份/数值）

对五个科目各给一句「这个科目在财报里长什么样」的说明，例如：
「合同负债」核算的是客户已付款、公司尚未确认收入的部分，也可能写作预收款项/预收账款，
资产负债表该科目的期末余额即提问所指金额。**这是解锁 Q6 的关键**——同一个模型、同一份材料，
没有这句回答「材料不足」，有了这句直接答出 7,529,047,335.12。

### 4. 材料拼装

`build_material` 单块 1200→900 字、总量 12000→16000 字（多公司题原先有 4~5 块被打成「上下文已满」），
末尾追加聚焦行视图；`MAX_TOKENS` 600→1100（12 家题要列得下）。

## 二、Q3 / Q6 / Q9 / Q10 四题记录

**Q3**

1. 召回块是否本来就含答案：✅ 原本就有：Top1 块#2919 p11 明写「传统渠道 86.96% / 新兴渠道 82.75%」

2. 优化前能否读出：❌ 答「营业收入257.31亿元」——没找到毛利率那一行，答非所问

3. 优化后：✅ 答「毛利率是86.96%[1]」，数字与引用都对（原文那条口径是「传统渠道运营模式」，模型未一并说明，算不完整但不再答错）

**Q6**

1. 召回块是否本来就含答案：✅ 原本就有：Top1 块#16425 p64「合同负债 | 7,529,047,335.12」、#16310 p22 同一金额带占比

2. 优化前能否读出：❌ 「材料不足」——问句是「经销商已打款未确认收入」，模型映射不到「合同负债」

3. 优化后：✅ 「合同负债7,529,047,335.12元[1]」，值/单位/引用全对

**Q9**

1. 召回块是否本来就含答案：✅ 原本就有：改前 Recall 侧已经是 12/12 家都有含营收同比的年报块

2. 优化前能否读出：❌ 「材料不足」——24 块里模型不敢横向比较，且原材料被打断成 5 处「上下文已满」

3. 优化后：✅ 12 家全部列出「营业收入 + 同比」，数值逐家核对**全部正确**，结论「山西汾酒 +7.52%」正确

**Q10**

1. 召回块是否本来就含答案：✅ 原本就有：12/12 家的首块都是主要会计数据表，含归母净利润与同比列

2. 优化前能否读出：⚠️ 只给出 9 个公司名，无数值、无引用，追溯 0/0

3. 优化后：⚠️ 12 家全部给出「归母净利润 + 同比 + 引用」，数值与单位全对、追溯 24/24；但结论把贵州茅台（-4.53%）以「未显著下滑」为由排除，自设了幅度门槛 → 共答 10/11 家


**是否出现新的数字/单位错误**：有一处，在中间版本出现、已在最终版修掉。

聚焦视图把「元」为单位的表格行顶到前面后，模型把别处的「万元」套了上去：
Q1 答成 `168,838,102,514.79万元`、Q2 答成 `6,439,313,574.11万元`、Q6 答成 `7,529,047,335.12万元`（都应為元）。
这是本轮改动引入的错误，靠两条修复：①聚焦视图不再对未标单位的块写「原文未标注单位」（该负向提示反而诱它猜单位）；
②提示词明确「表格行未标单位按财报披露惯例即为元」。最终版三题均为正确的「元」。

另一处残留：Q5 模型自行把两个子项相加给出「合计6,494,490,978.41元」，
被追溯校验判为不可追溯并已在回答里标出（提示词已明令禁止求和，4B 仍未完全遵守）。
